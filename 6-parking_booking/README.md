# Система бронирования парковочных мест

## Назначение
Система бронирования парковочных мест — учебное приложение для учёта парковочных мест, клиентов и бронирований.

Консольная версия, разработанная ранее, сохранена. Веб-интерфейс переведён на шаблоны Django.

Приложение позволяет:
* просматривать список парковочных мест;
* просматривать информацию о конкретном парковочном месте;
* просматривать список бронирований;
* просматривать информацию о конкретном бронировании;
* проверять доступность парковочного места на текущую дату;
* создавать и отменять бронирования в консольной версии;
* добавлять пользователей в консольной версии;
* хранить данные между запусками в JSON-файлах.

## Используемые технологии
* Python 3;
* Django 5.2;
* Django Template Language;
* HTML;
* CSS;
* JavaScript;
* Bootstrap 5.3;
* JSON;
* pytest;
* flake8.

## Предметная область
Основные объекты:
* парковочное место;
* пользователь;
* бронирование.

Пользователь может бронировать парковочное место на определённый период.
Одно парковочное место не может иметь два активных бронирования на пересекающиеся даты.
Отменённое бронирование не блокирует парковочное место.

## Хранение данных
Данные хранятся в JSON-файлах:
* data/spots.json;
* data/users.json;
* data/bookings.json.

Django ORM и база данных на текущем этапе не используются.

## Структура веб-шаблонов
* templates/base.html — базовый шаблон сайта;
* templates/includes/navigation.html — общая навигация;
* homepage/templates/homepage/index.html — главная страница;
* homepage/templates/homepage/not_found.html — страница 404;
* spots/templates/spots/spot_list.html — список мест;
* spots/templates/spots/spot_detail.html — страница места;
* spots/templates/spots/includes/spot_card.html — карточка места;
* bookings/templates/bookings/booking_list.html — список бронирований;
* bookings/templates/bookings/booking_detail.html — страница бронирования;
* bookings/templates/bookings/includes/booking_status.html — статус бронирования.

## Как работает веб-интерфейс
Представления получают данные из JSON-хранилища, формируют контекст и передают его в шаблоны через render().

В шаблонах используются:
* наследование через {% extends "base.html" %};
* блоки {% block title %} и {% block content %};
* включаемые фрагменты через {% include %};
* циклы {% for %};
* условия {% if %};
* обработка пустых списков через {% empty %};
* именованные URL и пространства имён через {% url %};
* фильтры length, default, date.

Генерация HTML внутри Python-представлений не используется. Функция page() удалена из веб-части проекта.

## Статические файлы
Статические файлы находятся в каталоге:
homepage/static/homepage/

Используются:
* css/style.css — собственные стили проекта;
* js/main.js — JavaScript для вывода текущего года;
* img/logo.png — логотип проекта.

Подключение выполняется через {% load static %} и {% static %}.

## Основные страницы
* / — главная страница;
* /spots/ — список парковочных мест;
* /spots/<int:spot_id>/ — парковочное место;
* /bookings/ — список бронирований;
* /bookings/<int:booking_id>/ — бронирование.

Если объект не найден, возвращается страница с кодом 404.

## Консольная версия
Консольная версия сохранена в файле main.py и использует те же модели и JSON-хранилище.

## Тестирование
Тесты предметной области находятся в каталоге tests/.

Запуск тестов:
pytest -v

Проверка качества кода:
flake8 . --extend-exclude=venv

## Запуск веб-сервера
python manage.py runserver

После запуска интерфейс доступен по адресу:
http://127.0.0.1:8000/

## Дальнейшее развитие
Дальнейшие этапы предполагают переход к Django ORM, базе данных и Django Forms.
